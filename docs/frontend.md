# Интерфейс Nero

Go + templ + Tailwind CSS 4 + htmx 4.0.0. HTML-обработчики вызывают сервисы напрямую; JSON API работает отдельно. Для операций с участниками ChatsService разрешает username через существующий UsersRepository. Связи в PostgreSQL и миграции не изменены.

## Запуск

```sh
npm ci
npm run build:ui
make run
```

`make run` использует `.env` и существующий PostgreSQL. Окружение и миграции подготавливаются как для обычного бэкенда. После изменения Go перезапусти процесс и обнови браузер.

При разработке: `npm run css:watch` и `make dev` в отдельных терминалах. Прокси templ сообщает свой адрес при запуске.

| Страница | Адрес |
| --- | --- |
| Главная | `/` |
| Регистрация / вход | `/register`, `/login` |
| Список разговоров | `/app` |
| Переписка | `/app/chats/{chat_id}` |
| Создание личного чата / группы | `/app/new`, `/app/new?type=group` |
| Свой профиль | `/app/profile` |
| Собеседник | `/app/users/{user_id}` |
| Участники и настройки группы | `/app/groups/{chat_id}` |
| Изменение пароля | `/app/password` |
| Подтверждение удаления аккаунта | `/app/account/delete` |

## Структура

- `internal/web/views/layout.templ`: каркас, шрифты и скрипты.
- `auth.templ`, `register.templ`, `login.templ`: вход и регистрация.
- `home.templ`: главная, логотип и SVG-иконки.
- `app.templ`: список чатов, переписка, сообщения, форма отправки.
- `profile.templ`: профиль, создание чата, группа и настройки аккаунта.
- `participants.templ`: поле поиска и карточки выбранных участников.
- `app.go`, `auth.go` в views: только данные для отображения.
- `internal/web/handlers/auth.go`: регистрация и вход через AuthService.
- `session.go`: cookie, обновление сессии и выход.
- `app.go`, `profile.go`, `routes.go` в handlers: HTML-маршруты и вызовы существующих сервисов.
- `web/styles/input.css`: палитра `@theme`, Tailwind, компоненты, адаптивность и анимации.
- `web/static/js/auth.js`: показ пароля и состояние формы авторизации.
- `web/static/js/app.js`: WebSocket, обновления, прокрутка, черновики и меню.
- `web/static/js/participants.js`: поиск с задержкой 250 мс, выбор участников, клавиатура и повтор запроса.
- `cmd/nero/main.go`: подключение интерфейса.

`*_templ.go`, `web/static/css/app.css` и `assets_generated.go` генерируются через `npm run build:ui`. Docker теперь сам собирает CSS, версии ресурсов и templ перед сборкой Go. Node нужен только на этапе сборки и не попадает в рабочий контейнер. Изменяй `.templ` и `input.css`, затем пересобирай. htmx, шрифты и SVG хранятся локально, CDN не нужен.

Адреса CSS и собственных JS содержат `?v=...` — первые 16 символов SHA-256 содержимого. При изменении файла браузер получает новый адрес вместо старой кешированной версии. Скрипт `scripts/build-assets.mjs` запускается автоматически после `css:build`; после изменения только JS можно выполнить `npm run assets:build` и пересобрать Go. Для `css:watch` сервер отдаёт `Cache-Control: no-cache`, чтобы браузер проверял обновление файла. После выпуска новой версии полностью обнови страницу: переходы через htmx заменяют содержимое страницы, но не её CSS и скрипты.

## Запросы и состояние

GET возвращает полный HTML. При переходе с `hx-get` сервер возвращает только `#app-root`, который htmx заменяет, обновляя URL. Восстановление истории с запросом возвращает полную страницу. Основные формы работают без htmx через обычный POST и перенаправление 303. Меню редактирования и realtime используют JavaScript.

Вход и регистрация принимают URL-encoded форму, вызывают AuthService и перенаправляют на `/app`. Пароль не возвращается в HTML. При ошибке сохраняются разрешённые поля; серверные ошибки не раскрываются.

Сообщение содержит `client_message_id`. При ошибке сохраняются текст и тот же UUID: повторная отправка использует существующую идемпотентность MessagesService. Новый UUID выдаётся после успеха. SenderID берётся из проверенного токена, а не из формы. Права на чтение, изменение и удаление проверяют существующие сервисы.

Черновики сохраняются в памяти вкладки при переходах через htmx. Обновление страницы очищает их. Во время отправки поле временно доступно только для чтения. Enter отправляет, Shift+Enter добавляет строку; ввод через IME не прерывается.

## Чаты и участники по username

Личный чат, группа и добавление участников используют поле поиска по началу username. От двух символов появляется до десяти активных пользователей с именем и username. Клик или Enter выбирает пользователя; стрелки перемещают фокус по результатам, Escape закрывает список. Выбранные участники отображаются карточками и удаляются по отдельности. Уже выбранные и существующие участники группы недоступны для повторного выбора. Не более 100 участников за запрос.

Поиск вызывает защищённый `GET /app/users/search?q=...`, затем `UsersService.SearchUsers`. Запросы отправляются после задержки 250 мс; предыдущий запрос отменяется, устаревший ответ не заменяет новую выдачу. Непустой незавершённый поиск нужно выбрать или очистить перед отправкой формы. Для группы можно не выбирать участников. Имена отправляются отдельными повторяющимися полями `participant_username`; личный чат использует `peer_username`. Без JavaScript можно ввести один полный username вручную.

Бэкенд также предоставляет `GET /api/v1/users/search?q=...&limit=10`. Поиск исключает самого пользователя и удалённые аккаунты, возвращает только публичные поля для выбора. Профиль инициатора проверяется перед выдачей. `_` в SQL LIKE экранируется как обычный символ. Постоянного кэша поиска нет. При большой базе для префиксного поиска понадобится оценить план SQL и подходящий индекс; миграция индекса сейчас не добавлялась.

Обработчик передаёт нормализованные имена в ChatsService. Сервис находит пользователей через `GetUserByUsername`, затем вызывает прежние операции по UUID с проверками прав и транзакциями. Повторные имена ищутся один раз в пределах запроса. Постоянного кэша имён нет: username может измениться.

При создании группы повторные имена объединяются, создатель автоматически становится владельцем. Если имя неизвестно или аккаунт удалён, группа не создаётся. При добавлении в существующую группу недоступные имена показываются в сообщении, остальные обрабатываются; серверная ошибка не считается частичным успехом.

Список участников показывает username. Кнопка «Написать» в профиле отправляет username. Удаление выбранного участника и выход используют скрытый UUID, чтобы смена username не меняла адресата уже открытой формы. Пользователь ID не вводит. URL чатов и профилей также используют стабильные UUID.

В JSON API изменены поля запросов: `peer_username`, `participant_usernames`, `target_username`. Старые поля с ID отклоняются. Точные примеры и ответы — в [описании API](http-api.md#chats-and-membership).

## Realtime

1. Защищённый `POST /app/session` возвращает access-токен. Refresh в ответ не попадает. Access используется только в памяти JavaScript.
2. Открывается существующий `/api/v1/ws`, отправляется `{type: "authenticate", access_token: "…"}`.
3. `message_created` запускает получение HTML после последнего курсора. Сообщения добавляются без замены формы отправки. Запросы объединяются; повторные события не дублируют сообщения.
4. Изменение обновляет текст безопасным `textContent`, удаление убирает сообщение. При восстановлении соединения перечитываются последние 50 сообщений для восстановления пропущенных изменений и удалений. Загруженная старая история при этом заменяется.
5. Прочтение отмечается при видимой вкладке и просмотре конца ленты. Новое сообщение не перематывает старую историю: появляется кнопка перехода вниз.

Точка возле списка показывает соединение вкладки с сервером. Статусы собеседника «онлайн» и «печатает» отсутствуют. Фильтр ищет только среди загруженных чатов.

## Cookie

- `nero_access`: HttpOnly, Path `/`, срок из `AUTH_ACCESS_TOKEN_TTL`.
- `nero_refresh`: HttpOnly, Path `/`, срок из общей конфигурации SessionTTL. Нужен HTML-маршрутам за пределами `/api/v1/auth`.
- `refresh_token`: прежняя cookie JSON API, Path `/api/v1/auth`; обновляется вместе с HTML cookie.
- SameSite=Lax, Secure в production. Пользовательские ответы имеют Cache-Control: no-store. POST защищён `http.CrossOriginProtection`.

Middleware проверяет access JWT. При истечении срока вызывает Refresh, обновляет cookie и пропускает запрос. Параллельные запросы одного процесса разделяют ротацию; результат хранится в памяти 5 секунд в ограниченном кэше. Реальные сессии остаются в PostgreSQL.

Выход вызывает Logout и очищает cookie. Изменение пароля и удаление аккаунта вызывают существующие сервисы, очищают cookie и кэш обновления пользователя.

HTML и JSON API используют один механизм ротации с отдельными копиями cookie. Не обновляй сессию одновременно через оба интерфейса: копия refresh-токена другого интерфейса может устареть.

## Ограничения существующего бэкенда

- Есть поиск по началу username. Поиск по имени/фамилии и по середине username пока не реализован.
- Нет загрузки аватара: используются инициалы.
- Нет событий присутствия и набора текста.
- Нет отдельного получения чата по ID. Экран проходит страницы ListChats текущего пользователя. Проверка доступа сохраняется, но число запросов растёт с количеством чатов. Участники группы также читаются целиком по страницам для определения текущей роли; большим группам понадобится отдельное получение своей роли.
- Refresh строго ротируется. Защита параллельной ротации в HTML действует в одном процессе. Нескольким экземплярам за балансировщиком понадобится согласованный механизм повторной ротации в авторизации; текущий кэш не обеспечивает это между процессами.
- Logout и изменение пароля удаляют refresh-сессии, но уже выданный access JWT живёт до истечения срока. Открытый WebSocket также может жить до срока JWT. Немедленный отзыв потребует отдельного решения в бэкенде.

Эти возможности не добавлялись в доменный слой: их можно разобрать и реализовать отдельно.

## Адаптивность и анимации

Страницы занимают весь браузер. Ограничена ширина формы и читаемой области сообщений. Как в `out/nero-desktop-preview.html`, мобильная раскладка включается при ширине меньше 620 px: авторизация скрывает декоративную панель; список чатов и переписка показываются отдельными экранами. От 620 до 800 px включительно действует компактная desktop-раскладка, выше 800 px — обычная. Высота приложения — `100dvh`, лента и настройки прокручиваются внутри своих областей. На телефоне текст полей ввода — 16 px.

Хедер переписки, хедер настроек и блок бренда в сайдбаре используют общий `--app-header-height: 72px`, поэтому их нижние границы совпадают. Вспомогательный текст приложения — 13 px, основной текст и поля на десктопе — 14 px; поля на телефоне — 16 px. Профиль использует две колонки на широком экране; ниже 1050 px форма располагается после карточки пользователя, а действия аккаунта — ниже формы. Полоса прокрутки профиля скрыта, но прокрутка мышью, касанием и клавиатурой сохраняется. Поле «О себе» имеет фиксированную высоту и `resize: none`.

Нижний блок профиля и форма отправки имеют общую базовую высоту 69 px на десктопе. `ResizeObserver` измеряет реальную высоту формы и передаёт её сайдбару через `--app-composer-height`, поэтому верхние границы совпадают при нескольких строках текста или сообщении об ошибке. После замены формы через htmx наблюдение подключается к новому элементу.

Размеры авторизации перенесены из внутреннего холста preview, без внешней рамки демонстрации. Орбитальный SVG вписывается через `background-size: contain` в область с отступами `90px -40px 240px`; на телефоне используется отдельная область 165 × 164 px. Изменять положение рисунка нужно в `web/styles/input.css`, а не растягивать сам SVG. Название Nero использует ту же цепочку шрифтов, что и preview: Manrope, Segoe UI, sans-serif; основной интерфейс — локальный IBM Plex Mono.

Переходы используют CSS и View Transitions через htmx; без поддержки браузером работает обычная замена HTML. Анимации короткие, орбитальный узор на главной движется медленно. При `prefers-reduced-motion: reduce` движение отключается.

## Проверки

```sh
go test ./...
go vet ./...
```

Тесты HTML-обработчиков проверяют ротацию параллельных запросов, выход после ротации, защиту межсайтовых POST, доверенный SenderID, повторную отправку с тем же UUID, сохранение текста при ошибке, безопасный вывод, очистку необязательных полей и порядок истории. Подставные сервисы не записывают данные в PostgreSQL.

Браузерные проверки — на временных данных: desktop и мобильные размеры, переходы htmx, отправка и изменение сообщений, realtime между вкладками, черновики и сохранение профиля. Это не интеграционная проверка PostgreSQL.

Справочники: [templ](https://templ.guide/), [Tailwind](https://tailwindcss.com/docs/), [htmx 4](https://four.htmx.org/docs), [CrossOriginProtection](https://pkg.go.dev/net/http#CrossOriginProtection).
